# Laqta — Transcription Performance Documentation

This document records the transcription performance work of October 2026:
the audit, the chosen defaults, the two-pass design, the transcript cache,
and the **real measured benchmark numbers** (with limitations stated).

---

## 1. Hardware context of the measurements

| Item | Value at measurement time |
| :--- | :--- |
| OS | Fedora Linux (x86_64) |
| CPUs | 4 threads |
| RAM | 7.7 GiB total; ~2.9 GiB available (desktop + browser running) |
| Runtime | Python 3.14.8, faster-whisper 1.2.1, CTranslate2 4.8.3, PyAV 19.0.1 |
| Model weights | `Systran/faster-whisper-base` (already cached in Laqta's model dir) |
| System load | Load average 2.9–3.7 DURING all runs (desktop in active use) |

Honest caveats:

- Samples are **synthetic espeak-ng speech** (built-in en-us/ar voices),
  generated by `tools/benchmark_transcription.py --make-samples`. They are
  synthetic *on purpose*: they make timing runs reproducible. They say
  nothing about ASR accuracy for real podcast speech.
- The machine was under real desktop load (3+ load average) and RTF > 1
  (slower than real time) at all times. Numbers reproduce the direction and
  rough magnitude of effects, and cross-run variance was ±10%; treat single
  seconds as noise.
- No accuracy metric is claimed anywhere; only time and memory.

## 2. What the audit found (before any change)

| Area | State before |
| :--- | :--- |
| Backend | faster-whisper 1.2.1 (CTranslate2 int8 CPU), lazy model load, per-process model cache |
| Full-video word alignment | **Always on** — `word_timestamps=True` was both the API default and the job-config default, so cross-attention word alignment ran for the entire video even though captions need words only for one selected clip |
| Speaker diarization | Not implemented (so also not "running unnecessarily") |
| Models reload | Not reloaded per job (in-process cache); page-cache-warm load ≈ 1.6–2.1 s |
| Audio | FFmpeg → 16 kHz mono PCM WAV; decoded via a whole-file `readframes` → `frombuffer` → `astype` chain that doubled transient memory |
| Extraction progress | Static 10% placeholder → 100% (not a real estimate) |
| Event loop | ASR in `asyncio.to_thread`, extraction as subprocess; single worker — OK |
| UI | Polled jobs every 1.5 s and displayed stage + percent — OK, but percent was unreliable for some stages |
| Transcript reuse | None. Identical re-transcription re-ran the entire ASR pass |

## 3. Chosen defaults and rationale

### Performance profiles (new)

| Profile | Model (config key) | Compute | Beam | Full-video word timestamps | Notes |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `fast` **(default)** | `QATTA_FAST_WHISPER_MODEL` = `base` | int8 | 1 | **No** | Today's model quality; segment-level timestamps for the full video |
| `balanced` | `QATTA_BALANCED_WHISPER_MODEL` = `small` | int8 | 1 | No | Better Arabic quality; ~2× decode cost vs base |
| `accurate` | `QATTA_ACCURATE_WHISPER_MODEL` = `medium` | int8 | 1 | **Yes** | Full-video word alignment; user-visible "takes longer" warning persisted in the job config |

Design decision — the default profile is `fast`, not `balanced`. Reasons:

1. `fast` keeps the same `base` model the app shipped with, so no user sees
   a *silent* quality/latency change; word precision is upgradable per clip
   (Pass B) without re-transcribing the video.
2. Measured between-run variance on this 4-core desktop is ±10%, and the
   AR-sample word-timestamp overhead was inside that noise envelope. The
   *predictable* wins are Pass A not paying for words at all plus cache
   reuse; making `small` the default model would have *cost* ~2× CPU time
   for everyone by default.
3. `balanced` and `accurate` remain one request field or env var away
   (`profile: "balanced"` etc.), and explicit `model_size`/`beam_size`/
   `word_timestamps`/`vad_filter`/`compute_type` request fields always win
   over the profile default.

One active transcription job is enforced as before by the single-worker job
queue (`DEFAULT_JOB_WORKERS=1`).

### Two-pass transcription

- **Pass A (full video, always)** — faster-whisper, profile-controlled,
  segment-level timestamps and transcript text; language auto-detect stays
  the default (`language: null`), explicit `language` is honored and passed
  through unchanged.
- **Pass B (selected clips only, on demand)** — when a render explicitly
  requests karaoke/animated word captions (`style.karaoke`) **and** the
  stored transcript has no word timings **and**
  `QATTA_CLIP_ALIGNMENT_ENABLED=true`, the render job:
  1. extracts ONLY the clip's audio (`-ss <start> -t <duration>`, bounded by
     `QATTA_MAX_CLIP_ALIGNMENT_SECONDS`, default 120 s) into the job temp
     dir,
  2. re-runs Whisper with `word_timestamps=True`, beam 5
     (`QATTA_CLIP_ALIGNMENT_BEAM_SIZE`) via a shared model cache,
  3. adds the clip offset once to convert local word times into absolute
     source-video timestamps (`convert_words_to_absolute`),
  4. validates word timings (bounds, monotonicity, within-clip range) and
     groups them by >1 s pauses into caption cues,
  5. on ANY failure returns to the well-tested segment-level caption path;
     the transcript is never discarded and the failure reason is recorded in
     the render config (`captions.alignment.reason`).

**Naming honesty:** Pass B is *clip-scoped Whisper word re-timing* (Whisper
cross-attention alignment inside the clip). It is **not** wav2vec2/WhisperX
forced alignment and **not** speaker diarization. No millisecond-exact
alignment claim is made anywhere; `captions.alignment` in the render config
records provider/model/beam/word_count for auditability.

### Transcript result cache

- Key = stream-`SHA-256(extracted WAV bytes + byte length)` XOR-bound with
  `SHA-256(settings)` and `CACHE_SCHEMA_VERSION=1`.
- Settings fingerprint includes ONLY fields that can change the transcript:
  model, language, beam, VAD, compute type, word-timestamp flag, profile,
  provider, WAV layout (16 kHz/mono), schema version. Captions, layout,
  crop, and export quality never invalidate the cache.
- Location: `<QATTA_DATA_DIR>/cache/transcripts/<key>.json` (never inside
  source dirs). Files are written atomically (`.tmp` → rename).
- On a hit the manager skips ASR entirely and still persists a fresh,
  immutable `TranscriptRecord` (history is preserved; links stay valid).
- Purge: `purge_transcript_cache(dir, older_than_days=None)` — full wipe or
  age-based.
- Measured cost: 18 ms fingerprint + 0.2 ms hit lookup for a 64 s sample
  (2.7 MB WAV) vs 67–115 s to re-transcribe.

### Memory / decode

The 16 kHz mono WAV is now decoded by a **chunked stream fill**: exactly one
pre-allocated float32 buffer plus ~2 MB int16 chunks, removing the old
whole-file bytes buffer + full-array copies. For a 1-hour video ~230 MB
(≡ 64 KB/s) peak stays *linear in duration* and bounded; the video stream is
never touched.

### Honest progress

- Extraction: real `out_time_ms` from `ffmpeg -progress pipe:1` (parsed
  when both a callback and a known media duration exist) → measured percent
  (capped 95%); falls back to indeterminate behavior when no duration.
- ASR: percent derived from actual audio position `(seg.end / duration)`
  — a true estimate, unchanged.
- New `indeterminate: bool` on `JobResponse` (true for `starting`,
  `loading_model`, `loading_clip_alignment_model`, `aligning_selected_clips`,
  `restored_from_cache`); UI shows stage + elapsed time instead of a percent
  in that case.
- Cancellation cleans the per-job temp directory (`cleanup_job_temp_dir`),
  so cancelled jobs leak no partial WAV/part files.

## 4. Benchmark results (measured, this machine, as configured in §1)

Reproduce with:

```bash
cd backend
.venv/bin/python tools/benchmark_transcription.py --make-samples --seconds 60
# 'before' (legacy full-video word timestamps):
.venv/bin/python tools/benchmark_transcription.py \
  --audio /tmp/qatta_bench/sample_en.wav --language en --word-timestamps
# 'after' (default Pass A, no word timestamps):
.venv/bin/python tools/benchmark_transcription.py \
  --audio /tmp/qatta_bench/sample_en.wav --language en
# Pass B measurement:
.venv/bin/python tools/benchmark_transcription.py \
  --audio /tmp/qatta_bench/sample_en.wav --language en --clip-alignment
```

### Stage timings (base, int8, beam 1, VAD on, 4 threads)

| Metric | EN 64.46 s sample | AR 74.18 s sample |
| :--- | :--- | :--- |
| Model load (warm page cache, cold process) | 1.57–2.07 s | ~1.6 s |
| Audio decode to float32 (2.7 MB WAV) | 0.08–0.13 s | same order |
| Peak RSS after model load | 351 MiB | 351 MiB |
| Peak RSS end of Pass A | 586–587 MiB | 596 MiB |

### Pass A: before vs after word timestamps

| Sample | Before (word_timestamps=True) | After (word_timestamps=False) | Δ |
| :--- | :--- | :--- | :--- |
| EN 64.46 s (2 runs each) | 73.08 s, 74.70 s (RTF 1.134 / 1.159) → **avg 73.9 s** | 67.50 s, 68.13 s (RTF 1.047 / 1.057) → **avg 67.8 s** | **−8.3% wall time** (~9% for the 25.3 s sample too: 38.0/34.8 vs 37.4/39.2 s — overlapping; stated only as "consistent trend on EN") |
| AR 74.18 s | 113.64 s (RTF 1.532), 1 run | 106.89 s, 114.64 s (RTF 1.441 / 1.545) | **within run-to-run noise; no claim** |

Interpretation (honest): dropping the full-video word pass removes a real
but **modest** cost with the `base` CPU model (~6–9% on the EN sample). The
larger structural wins are:

1. **Word precision is now bounded by clip length, not video length.** Pass
   B measured 37.9–46.7 s (RTF 1.26–1.56, noisy) for a 30 s clip window in
   the same process-equivalent conditions; whether the user picks one clip
   or ten, the cost stays per-selected-clip — a 50 min video would pay for
   its 30–55 s selected window, not ~RTF×3000 s.
2. **Cache makes repeat ASR free** (measured above: 18 ms + 0.2 ms vs one
   full pass).
3. **No per-job model reload** (unchanged, verified: warm load 1.6–2.1 s).

### Benchmark reproducibility caveats (observed, then fixed in procedure)

- Early single runs with a 32 s sample produced contradictory RTFs (±35%)
  while the desktop was heavily loaded; later multi-run methodology
  (§ commands above) is stable to ±3%.
- One early Pass B run reported `words_absolutized: 0`; an isolated
  deterministic re-run on the same slice produced correct segmentation at
  beam 1 (3 segments/20 words) and beam 5 (9 segments/63 words). Attributed
  to system-load noise affecting the loaded environment, not to a code path;
  the render-time alignment service additionally **fails safe** (falls back
  to segment captions) when zero/invalid words are detected, which the unit
  tests cover (`test_align_clip_words_raises_when_no_words`).
- Beam-size effect on Pass B (EN slice 10–40 s): beam 1 → RTF ~0.85 (drops a
  low-intensity sentence); beam 3 → ~1.04; beam 5 → ~1.27 (full speech
  captured). Default stays 5 because Pass B is clip-sized and coverage beats
  a ~25% relative saving on ≤55 s of audio.

### Cache and progress checks

| Check | Result |
| :--- | :--- |
| Fingerprint + settings hash (2.7 MB WAV) | 18.1 ms |
| Cache-hit lookup (load + validate) | 0.2 ms |
| `ffmpeg -progress` extraction reporting | 10 → real out_time curve → 100 (verified on a 10 s fixture) |

## 5. What was NOT done (explicit non-goals)

- Speaker diarization: not implemented; nothing pretends otherwise.
- WhisperX / wav2vec2 alignment: intentionally not added (heavy, HF-tokened,
  torch-sized dependency chain for an 8 GB CPU-first box). Pass B reuses the
  already-downloaded CTranslate2 stack instead.
- Large batch decoding: not enabled; would trade RAM safety on 8 GB.
- Accuracy benchmarking: out of scope; TTS samples measure timing only.

## 6. Operational knobs

## 7. Core package two-pass stages (qatta/stages)

Design notes for stage `s01_ingest` and stage `s02_transcript` (Pass 1 in
`fast_pass.py`, Pass 2 in `fine_pass.py`). Facts stay honest here — none of
the items below claim measurement:

- Pass 1 params: `beam_size=1`, `word_timestamps=False`,
  `condition_on_previous_text=False`, `vad_filter=True`,
  `BatchedInferencePipeline` batch auto-tuned (CUDA → 16 / CPU → 4; CPU
  default targets the 8 GB box), compute_type `int8` (CPU) /
  `int8_float16` (CUDA).
- The Groq cloud adapter (opt-in + explicit `QATTA_ALLOW_CLOUD_APIS` +
  key) chunks the 16 kHz WAV into `.ogg` 32 kbps slices (default 15 min)
  and posts them with bounded concurrency (default 4) and 2 bounded
  retries. Chunk offsets are converted back to absolute milliseconds
  before merging.
- Acoustic pause merge is pure-numpy RMS energy gating (no
  librosa/silero added); segments split only when a real ≥350 ms silence
  occupies the gap (`QATTA_PAUSE_SPLIT_MS`).
- Pass 2 slices ONLY `[clip.start_ms ± QATTA_FINE_PADDING_MS]` (default
  ±2 s per winning clip, never the whole video), re-times words with
  `word_timestamps=True`, `beam_size=QATTA_FINE_BEAM_SIZE` (default 2),
  `vad_filter=False` (VAD trimming would shift slice-relative offsets),
  then snaps clip boundaries to first/last word ± 120 ms
  (`QATTA_SNAP_PAD_MS`). Alignment failure degrades to the original
  boundaries plus an `evidence_log` note; it can never fail a candidate.
- Test coverage for the above uses synthetic numpy-burst WAVs and mock
  adapters (offset math, gating, snapping verified); a REAL-WEIGHTS smoke
  test exists behind `QATTA_TEST_REAL_WEIGHTS=1`. Stage-throughput
  benchmarks (large-v3-turbo vs base on real Arabic/English lectures) are
  pending and will be recorded here ONLY after being measured on this
  machine.


See `.env.example`. Everything below is a plain env override:

- Profiles & models: `QATTA_DEFAULT_WHISPER_PROFILE`,
  `QATTA_{FAST,BALANCED,ACCURATE}_WHISPER_MODEL`
- Decode: `QATTA_WHISPER_CPU_THREADS` (default 4 = this machine's cores),
  `QATTA_DEFAULT_WHISPER_COMPUTE_TYPE`, `QATTA_WHISPER_BEAM_SIZE`,
  `QATTA_WHISPER_VAD_FILTER`
- Pass B: `QATTA_CLIP_ALIGNMENT_{ENABLED,MODEL,BEAM_SIZE}`,
  `QATTA_MAX_CLIP_ALIGNMENT_SECONDS`
- Cache: `QATTA_TRANSCRIPT_CACHE_ENABLED` (purging: delete
  `<data_dir>/cache/transcripts/` or call `purge_transcript_cache()`)

Model weights stay in `<QATTA_DATA_DIR>/models/whisper` (unchanged layout;
pre-download for air-gapped hosts as documented in
`TRANSCRIPTION_TRADEOFFS.md` §3).
